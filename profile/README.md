<p>关于独享出口到底值不值，争论通常停在感受层面："我感觉稳了""我觉得没差"。想拿到可用的结论，得把它做成一次对照实验：两组只差一个变量，同样的任务、同样的时间窗、同样的判定规则，跑够样本量再看差值。下面这套设计只用一台机器和一个脚本就能完成，重点在于控制变量和读数规则，而不在于数字本身有多漂亮。</p>

<h2>一、实验设计：两组之间只允许差一个变量</h2>
<p>最容易犯的错是一次改两个条件，比如既换了出口又换了浏览器配置，最后不管结果好坏都说不清原因。正确做法是把变量列出来，一次只动一个。</p>
<h3>控制住这四项</h3>
<p>请求体与调用时间窗保持一致；账号的历史状态尽量相近（都是正常可用、近期无异常）；观测设备的本地网络不变；记录的人员固定，避免主观判断差异。四项里任何一项变了，实验就得重做。</p>
<h3>样本量与观测窗口</h3>
<p>每组每天二十次登录动作、连续五天，合计一百次，是比较省时又不至于被偶然性淹没的规模。窗口要覆盖工作日和周末各一段，否则峰值特征看不全。</p>

<h2>二、第一组：独享出口与共用出口</h2>
<p>这是最常被讨论的一组。设计上让两组账号数量、活跃时段、任务类型完全一致，唯一差别是 B 组每两个号共用一条出口地址。</p>
<h3>观测什么</h3>
<p>主指标是首次登录一次通过率，即不需要验证、不需要二次确认就进入的次数占总次数的比例。辅指标是需人工介入次数和首字节 P95。前两个指标看稳定性，最后一个看性能，不要混在一起评价。</p>
<h3>判定规则</h3>
<p>差值超过二十个百分点、并且五天的方向一致，才认为存在真实差异；差值在十个百分点以内、或者几天里方向来回翻转，判定为本次实验无法区分。这条规则能挡掉大部分"看起来有用"的错觉。</p>

<h2>三、第二组：固定地址与按会话切换</h2>
<p>这一组针对的是地址漂移的影响。A 组在租期内固定一条地址，B 组使用按会话分配的地址，每次新会话地址可能变化，其余条件相同。</p>

<h3>重点看漂移次数与异常的相关性</h3>
<p>在 B 组单独记一张漂移表：每次会话记录返回地址与时间。事后把出现验证的时间点和漂移时间点对齐，如果验证总是紧跟漂移出现，相关性就很清楚；如果两者无关，说明问题不在地址层。</p>
<h3>性能上的差异往往被低估</h3>
<p>按会话切换的出口在建立连接时多一次分配，首字节时间通常会更长一些。这部分差异对批量任务不敏感，对流式交互就明显。所以这一组的结论要按业务类型分开下，不能一句话概括。</p>

<h2>四、第三组：交接时重建环境与保留环境</h2>
<p>账号交接给同事是很多团队的日常动作，但很少有人量化它的影响。这一组让 A 组保持原出口与原浏览器配置，B 组在新设备上重建一套环境（新出口、新配置），观察接手后前三天的表现。</p>
<h3>怎么设计才公平</h3>
<p>两组的账号历史要匹配，避免把"老号"和"新号"混在一起比较。接手人固定，操作流程写成同一份清单，避免人为差异。观测窗口取接手后三天，正好覆盖第一次完整使用周期。</p>
<h3>记录交接耗时</h3>
<p>除了成功率，还要记交接本身的耗时：A 组只需核对配置和移交文档，B 组需要重建环境再逐项验证。这个耗时是一次性成本，但在频繁交接的团队里会反复发生，累计起来不小。</p>

<h2>五、怎么读结果：先看差值方向，再看幅度</h2>
<p>实验做完会得到一堆数字，读的时候要按顺序：先确认三组的差值方向是否与假设一致，再看幅度是否超过判定线，最后才看绝对值。顺序反了容易被个别漂亮数字带偏。</p>
<h3>把结果放进一张表</h3>
<p>每行一个对照项，每列一个指标，最后一列写结论。结论只允许三种：有差异、无差异、无法判定。不允许写"总体感觉更好"这种无法复核的判断。</p>
<h3>结论要能指导下一步</h3>
<p>如果第一组显示差异明显，就把"独享"写进采购标准；如果第二组显示漂移与验证强相关，就要求固定地址；如果第三组差异不大，说明交接流程本身设计得够好，可以继续沿用。每个结论都要挂一个具体动作，否则实验白做。</p>

<h2>常见问答</h2>
<h3>样本一百次够不够？</h3>
<p>答：用来发现大幅差异足够，用来判断小幅差异不够。如果两组差值只有几个百分点，需要把样本加到三百次以上，并且拉长观测窗口，否则结论很容易被单日波动推翻。</p>
<h3>实验中账号真被要求验证了怎么办？</h3>
<p>答：按既定流程处理，不要临时改配置。改配置等于引入新变量，这一轮数据只能作废重来。处理过程本身也要记录，它是人工介入次数的来源。</p>
<h3>能不能用同一批账号做两组？</h3>
<p>答：不建议。同一个号先跑 A 再跑 B，前一轮留下的会话痕迹会影响后一轮，这就是顺序效应。要么准备两批状态相近的号，要么用交叉设计并拉长间隔。</p>
<h3>结论可以推广到别的地区吗？</h3>
<p>答：不能直接推广。不同地区的运营商互联质量差别很大，本地测出来的结论只对本地有效。换地区要重做一轮，至少覆盖一个晚高峰。</p>
